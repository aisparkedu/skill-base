# 公众号图文与解释型配图

读文章、提炼信息、规划图组、生成与校对共用一套流程。风格模板只决定视觉表达，不决定文章主题、知识顺序或图片数量。

## 先确定风格与交付方式

### 风格选择

| 用户说法 | 模板 | 必读资源 |
|---|---|---|
| 老模板、老风格、暖奶油、蓝橙绿、纸雕 | `warm-cream` | [老模板规则](references/styles/warm-cream.md)、[原有提示词](references/prompt-templates.md) |
| 新模板、新风格、钢笔手绘、钢笔杂志 | `steel-pen-magazine` | [钢笔杂志规则与提示词](references/styles/steel-pen-magazine.md) |

明确指定优先；继续当前任务时沿用已确认风格；没有任何风格上下文时用老模板，保持原有调用行为。换风格不改变已确认的核心文案。每次只读取并传入所选模板的参考图，不混合两套配色和笔触。

### 交付方式

- **总结图**：用户要把文章浓缩成几张图、图片为主或公众号总结图时，读取 [总结图规划](references/summary-planning.md)。图片应独立讲清核心内容，两种风格均可使用。
- **正文配图**：用户要文章封面、章节配图或解释型插图时，读取 [原有规划规则](references/planning-rules.md)。默认一张封面，加确实帮助理解的章节图。较长教程可参考一张封面加四至七张解释图，不是固定数量。
- 单纯更换风格时沿用当前交付方式。明确是正文配图时，不能因选择钢笔杂志就擅自改为整篇总结图。

总结图使用自己的内容密度和首图规则，不受正文配图“少量标签、配合段落阅读”的限制。模板中的配色、字形和插画规则始终有效。所有资源路径均相对于技能根目录。

## 依赖与使用

- 宿主需要可用的图像生成工具，支持文生图及本地参考图输入；优先使用内置能力。这个技能包包含规则和参考素材，模型服务由宿主提供。没有生图工具时说明缺少该能力，提供已规划的文案和提示词供用户接入工具，不把提示词当作生成图片交付。
- 尺寸处理脚本需要 Python 3 和 Pillow。安装依赖：`python3 -m pip install Pillow`。
- 安装时复制整个 `wechat-explainer-images` 文件夹，包括 `assets/`、`references/`、`scripts/` 和 `agents/`。
- 调用示例：“用钢笔杂志风，把这篇文章做成公众号总结图。”或“用老模板做这篇文章的封面与章节配图。”

## 共用流程

1. 完整读取源文章及已有素材，包含标题、正文、表格、截图和来源。优先使用用户指定文章，不能仅凭标题编造内容。
2. 确认上述交付方式和风格，读取对应规划与模板。先查看所用参考图片，再调用可用的图像生成工具，优先使用内置能力。
3. 生成前列出图文计划：文件名、页序或插入位置、沟通目的、准确标题与全部图内文案、图解关系、参考图。图数随内容决定。
4. 一张图一个生成调用。参考图仅控制风格、间距、轮廓和层次，不能照搬其中的产品、文字、代码、图标主体或统计。后续图片可追加本套已通过检查的首图作为一致性参考。
5. 逐张核对文字、阅读顺序和图解关系。有错误时仅修正具体区域；需要实际界面证据时使用真实截图，生成图不能伪装成截图。
6. 保留原始生成图。对通过检查的图片运行 `scripts/normalize_image.py 输入图片 输出图片`，最终交付为1080×1440、竖版3:4，等比处理，不拉伸裁切。
7. 保存到当前项目资产下的新版本目录。遵循项目已有目录约定；没有约定时使用 `assets/{项目名}/infographic/{风格-版本}/`。保存实际使用的完整提示词、风格标识、文案与图片索引到中文说明文件；不覆盖既有图片。
8. 全部通过检查后，按任务需要交付独立图组或插入正文，并更新项目产物索引；验证图片链接存在。保存素材不等于获得公开发布授权。

## 共用检查

- 中文无错字、漏字、重复、裁切；技术字段与代码逐字符检查，代码另附可复制文本。
- 读者能辨认本页结论、主体与下一步；总结图不依赖图外段落补足关键关系。
- 箭头起点、终点、步骤次序正确；并列观点不强行串成流程。
- 不伪造统计、价格、实测结果或软件界面。原文涉及易变化信息时核对来源或明确省略。
- 图片增加结构，不是把段落缩小后塞进卡片；装饰不遮挡信息。
- 同套图字形、颜色、页眉与页码一致，版式可随内容变化。
- 最终1080×1440；索引与图片链接有效。

## 维护约束

这是一个 skill 下的并列风格模板。新增或调整某套风格只修改它自己的规则与参考图。原有 `assets/cover-style-reference.png`、`assets/explainer-style-reference.png`、`references/prompt-templates.md` 和老模板风格规则保持原样，除非用户明确要求修改老风格。
