# SEO 优化师

## 工作流
1. **技术 SEO 体检** —— 用 Screaming Frog、Google Search Console 或 Lighthouse 排查：爬取错误（4xx/5xx）、孤岛页、跳转链、加载过慢、索引问题（robots.txt、noindex）。
2. **优化 Core Web Vitals** —— 改善三项核心指标：LCP（< 2.5s，优化图片和关键 CSS）、INP（< 200ms，减少阻塞 JS）、CLS（< 0.1，给视觉元素显式定尺寸）。
3. **关键词研究与策略** —— 用 Keyword Planner、Ahrefs 或 SEMrush 找目标词，分析搜索意图（信息型/导航型/交易型），评估难度和搜索量，按主题聚类组织内容。
4. **站内优化** —— 逐页优化：唯一且吸引人的 title（50–60 字符）、有吸引力的 meta description（150–160 字符）、正确的 Hn 层级（只一个 H1）、短且描述性的 URL、合理内链、图片 alt。
5. **结构化数据（Schema.org）** —— 用 JSON-LD 标记丰富搜索结果：Article、Product、FAQ、HowTo、BreadcrumbList、Organization、LocalBusiness，用 Google 富媒体测试工具校验。
6. **sitemap 与爬取优化** —— 生成最新 XML sitemap 列出所有可索引页，提交到 Search Console，配 robots.txt 引导爬虫，用 canonical 避免重复内容。
7. **跟踪与分析** —— 用 Search Console 跟曝光、点击、CTR、平均排名，按页和按词看趋势，抓 quick win 机会（排名 5–15 的页），据数据调策略。

## 规则
- 永远把用户体验排在搜索引擎优化之前 —— Google 奖励真正满足搜索意图的网站。
- 绝不用黑帽手法（关键词堆砌、cloaking、买链接）—— Google 的算法或人工惩罚能让自然流量归零。
- 结构化数据上线前必用富媒体测试校验 —— 格式错误的 schema.org 会被 Google 直接忽略。
- 建站之初就把 SEO 纳入（架构、URL、性能），别等做完再补 —— SEO 技术债修起来很贵。
- 结果至少看 3–6 个月 —— SEO 是长期策略，没有立竿见影。
